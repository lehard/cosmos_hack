# S12. Некорректные сообщения — карантин с кодами

> Все изделия, числа, ID, даты и люди — условные. Коды ошибок — наши рабочие, окончательные задают разработчики.
> Статус: сценарий и данные готовы. Как система проходит сценарий — по плану, проверить по факту у разработчиков.

**Где идёт.** Главная история, фон: Вт 22.09 14:00. Можно прогнать отдельно.

## Проверяет

- **Постановка:** §4.7 — неизвестная версия, новое необязательное поле, нет обязательного поля, неизвестное значение; версия контракта отдельно от версии анализатора; §4.6 — ненадёжная идентификация объекта обозначается явно.
- **Строки листа:** ОК-3 и ТК-7 «Модуль сбора и обработки данных» (15 + 15) — проверка входов; ОК-8 «Предотвращение рассинхронизации» (5); ОК-6 «Расширяемость» (5) — новое поле принимается.

## Исходное состояние

- Приём событий работает по контракту версии 1.0; анализатор камер — отдельная версия `vqc-weld 2.3.1`.

## Действие

Имитатор подмешивает шесть сообщений: без номера изделия; с версией контракта 9.0; с исходом «maybe»; версии 1.1 с новым необязательным полем; с неизвестным классом дефекта в некритичном поле. Администратор исправляет первое (номер изделия — по контексту поста) и отправляет из карантина повторно.

## Ожидается

- В карантине три сообщения с кодами: нет поля, неизвестная версия, неизвестное значение — `S12-01`.
- У каждого — поле или значение, источник, время — `S12-02`.
- Новое необязательное поле принято и сохранено как есть — `S12-03`.
- Неизвестный класс в некритичном поле принят с флагом «неизвестно» — `S12-04`.
- Исправленное сообщение принято ровно один раз — `S12-05`.
- Качество потока: «в карантине» +3 — `S12-06`.

## Чего не должно случиться

- Показатели качества не меняются от сообщений 1–3 — `S12-N1`.
- «maybe» не превращается в «признаков нет» — `S12-N2`.
- Номер изделия не угадывается без человека — `S12-N3`.
