# S16. Ненадёжная привязка события к выполнению операции (Ф-004 / Ф-005)

> Все изделия, числа, ID, даты и люди — условные. Уровни привязки — наше допущение.
> Статус: сценарий и данные готовы. Как система проходит сценарий — по плану, проверить по факту у разработчиков.

**Где идёт.** Главная история, фон: Пт 18.09 12:55–15:20. В 4 минуты не входит, видно на табло.

## Проверяет

- **Постановка:** §4.6 — «при ненадёжной идентификации объекта или операции это обозначается явно» (здесь — операция); §4.3 — изменение режима.
- **Строки листа:** ОК-3 и ТК-7 «Модуль сбора и обработки данных» (15 + 15).

## Исходное состояние

- Оператор О-11 на станке ЧПУ-1 заканчивает Ф-004 и начинает Ф-005. «Закончил» по Ф-004 он нажал с опозданием — по терминалу два выполнения перекрываются 70 секунд.

## Действие

В это перекрытие с пульта станка приходит запись «подача 120 % на 80 с» — без номера выполнения и без исполнителя. Система не выбирает «на глаз»: пишет «неоднозначно», два кандидата и основания.

## Ожидается

- Уровень привязки «неоднозначно», два кандидата, вероятный назван, но фактом не стал — `S16-01`.
- Кто работал на станке — известно по терминалу, от неоднозначности не зависит — `S16-02`.
- Вывод «было ли ручное изменение режима» у обеих деталей — «не установлено» — `S16-03`.
- Остальное по Ф-004 и Ф-005 без оговорок: КИМ, камера, ЗТ-2 с первого раза — `S16-04`.
- Качество потока: «неоднозначная привязка» +1; изменение режима у станка посчитано один раз — `S16-05`.

## Чего не должно случиться

- Запись не приписана одному выполнению и не раздвоена на два — `S16-N1`.
- Нет сигнала, несоответствия и блока изделий — `S16-N2`.
- Событие не идёт в показатели по людям — `S16-N3`.
