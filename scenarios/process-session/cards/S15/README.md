# S15. Сдвиг часов источника: часы КИМ-1 спешат на 7 минут

> Все изделия, числа, ID, даты и люди — условные. Правило исправления времени — наше допущение.
> Статус: сценарий и данные готовы. Как система проходит сценарий — по плану, проверить по факту у разработчиков.

**Где идёт.** Главная история, фон: Пн 21.09 08:25–10:15. В 4 минуты не входит, видно на табло.

## Проверяет

- **Постановка:** §4.6 — расхождения времени источников; §5.2 — понятно, откуда взято время.
- **Строки листа:** ОК-3 и ТК-7 «Модуль сбора и обработки данных» (15 + 15) — обработка времени и порядка.

## Исходное состояние

- После выходных КИМ-1 не синхронизировал часы: они спешат на 7 минут. Записи КИМ-1 при этом идут строго по порядку номеров.

## Действие

Протокол КИМ по Ф-007 приходит со временем события 08:32 при получении 08:25 — «из будущего». Система видит сдвиг, сообщает администратору и ставит рядом исправленное время по правилу. Так же — ещё четыре протокола. В 10:15 администратор синхронизирует часы, следующая запись — без поправки.

## Ожидается

- Сдвиг +7 мин найден, администратор предупреждён — `S15-01`.
- Исходное время сохранено, рядом — исправленное с пометкой — `S15-02`.
- Исправлено 5 записей КИМ-1 — `S15-03`.
- Порядок записей по номерам не нарушен, ничего не переставлено — `S15-04`.
- В истории протокол КИМ стоит до подписи ЗТ-2 — `S15-05`.
- После синхронизации — без поправки — `S15-06`.

## Чего не должно случиться

- Решения ЗТ-2 не получают ложную метку «пересмотрите» — `S15-N1`.
- Записи со сдвигом не уходят в карантин — `S15-N2`.
- Исходное время не перезаписано — `S15-N3`.
- В показателях ожидания нет отрицательных интервалов — `S15-N4`.
