# S07. Позднее событие — опоздавший журнал ИС-2 пересматривает вывод

> Все изделия, числа, ID, даты и люди — условные.
> Статус: сценарий и данные готовы. Как система проходит сценарий — по плану, проверить по факту у разработчиков.

**Где идёт.** Главная история, Вт 22.09 09:50 – Ср 23.09 14:05. В защите — 1:30–2:20.

## Проверяет

- **Постановка:** §4.2 «поздняя доставка»; §5.1 «Задержка» — история обновляется по правилам; §4.6 — задержки и нарушение порядка; §5.2 — обновление после позднего события.
- **Строки листа:** ОК-3 и ТК-7 «Сбор и обработка данных» (15 + 15) — задержки; ОК-2 и ТК-6 «Сквозной процесс» (15 + 15) — пересмотр решения; ОК-5 (5); ТК-3 (5).

## Исходное состояние

- Во Вт 09:50 шлюз ИС-2 теряет связь и копит журнал у себя.
- Во Вт 15:30 ОТК-1 подписала ЗТ-3 по Ф-015 с итогом «годно при неполных данных»: камера и рентген чистые, журнала нет.

## Действие

Через 15 минут без данных система предупреждает администратора и спрашивает мастера «остановить пост?» — ответа нет. В Ср 12:05 шлюз досылает журнал. Ключевая запись EV-WS2-0412: ток 176 А во Вт 10:20. Записи встают на своё время, гипотезы и показатели пересчитываются, на подписанном решении по Ф-015 появляется метка «пересмотрите». В 14:05 ОТК-1 пересматривает его с итогом «отозвано».

## Ожидается

- Через 15 минут без журнала — «нет данных от ИС-2» и вопрос мастеру — `S07-01`, `S07-10`.
- Ключевая запись встала на время события, помечена «опоздало» — `S07-02`.
- Гипотезы НС-01: новая версия с пометкой, старая видна — `S07-05`.
- На ЗТ-3 Ф-015 — метка «принято до новых данных — пересмотрите» — `S07-06`.
- Показатели прошлых дней пересчитаны с пометкой — `S07-07`.
- Пересмотр — новая запись ОТК-1 «отозвано», исходная подпись сохранена — `S07-09`.

## Чего не должно случиться

- Опоздавшие записи не датируются временем получения — `S07-N1`.
- Подтверждение НС-01 не меняется — `S07-N2`.
- ЗТ-3 по Ф-015 не отменяется сама — `S07-N3`.
- В 1С ничего не уходит повторно из-за пересчёта — `S07-N4`.
