# Процессный набор сценариев — «плохой день сварочного участка»

> Все изделия, числа, ID, даты и люди в сценариях — условные, это не данные «Энергии».

**Что это.** Эталон процессной сессии для фланца люка: сюжет «плохой день сварочного участка» — главная история MAIN-STORY (MS-1, «Плохой день ИС-2»), сценарии S01–S22 и обмен с 1С I1. Всего **445 машинных утверждений** «ожидалось → получилось», они хранятся отдельно от входных событий (кейс §5.1).

**Статус — честно.** Набор **не подключён к `make`** и к прогонщику сценариев системы: исполняемые сценарии «Главного» лежат в `scenarios/definitions/` и `scenarios/expected/` (см. [scenarios/README.md](../README.md)), а этот каталог — эталон для сверки: что должна показать система на тех же событиях. Сценарии **S14–S22 в код не подключаются** (до защиты — только описание, данные и ожидания). Сведение имён событий и полей с контрактами `contracts/` — по плану, отдельным шагом.

**Термины.** Слова в данных, ожиданиях и полном описании — процессной сессии. Соответствие словам системы: «удержание / придержано» = «блок / заблокировано», статус поста «Остановлен (блок)»; предложения показывает система в блоке «инженерная справка» (внутренний помощник: подсказывает, не решает). Схема процесса, по которой написаны сценарии, — [docs/process/flange-process-v0.3.2.bpmn](../../docs/process/flange-process-v0.3.2.bpmn) (описательная; исполняемая — `normative/`).

## Как пересобрать и проверить

Из каталога `scenarios/process-session/`:

```sh
python3 emulator-data/tools/generate.py        # потоки streams/ и шаги людей definitions/scenarios/
python3 emulator-data/tools/split_expected.py  # expected/scenarios-flange-expected.yaml → emulator-data/expected/<ID>.yaml
python3 emulator-data/tools/check.py           # все проверки данных; итог — «ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ»
python3 check_cards.py                         # карточки ↔ YAML ↔ оглавление
```

Нужен Python 3 и PyYAML. Пути в скриптах — относительные от файла скрипта, запускать можно из любого каталога.

## Как читать

- **Утверждение** — одна машинная проверка «ожидалось → получилось». В карточке — 3–7 ключевых, остальные — в YAML сценария.
- **Строки листа оценки:** ОК — отраслевые критерии, ТК — технические. ОК-2 и ТК-6 — одна и та же строка «Сквозной процесс контроля качества и работы с браком» у двух жюри; ОК-3 и ТК-7 — «Модуль сбора и обработки данных». Как система закрывает каждый критерий — [docs/case-compliance.md](../../docs/case-compliance.md).
- **Прогон:** «главный» — сценарий идёт внутри главной истории, его прогоняют как `main-story` до своей контрольной точки; «отдельный» — свой поток и свой seed.
