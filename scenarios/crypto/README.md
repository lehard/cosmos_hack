# scenarios/crypto — материалы смены ключа и криптопрофиля

Кейс §6.3, FR-76, критерий О9; спайн AD-10, AD-11, AD-26, AD-32. Жизненный цикл ключей — `docs/crypto.md`.

В каталоге только **открытые** ключи и подписанные пакеты: закрытые ключи генерации выбрасываются сразу после подписи
(в промышленной эксплуатации материалы создаёт `ant init` на своих ключах — эпик 05).

| Файл | Что это |
|---|---|
| `registry.jsonl` | реестр ключей и профилей — записи `key.registration.recorded`, `key.profile.registered`, `key.revocation.recorded` с `seq` и `committed_at`, как в журнале; поле `note` — пояснение |
| `packages/*.json` | подписанный пакет DSSE, момент подписи (`seq`, `committed_at`) и ожидаемый вердикт |

| seq | Запись |

| 1, 2 | ключи контролёра INS-01: ГОСТ Р 34.10-2012 `ins-01@1` и ML-DSA-65 `ins-01-pq@1` |

| 4 | ключ `ins-02@1` второго контролёра |
| 100 | **смена профиля**: пакеты класса `event` — `hybrid` (ГОСТ + ML-DSA-65, обе подписи обязательны) |

## Переход между профилями (FR-76: «описан переход»)

- **Старый формат** поддерживается: пакеты `gost` до смены остаются «цело» навсегда — профиль берётся из реестра на момент подписи, историю не переподписывают.
- **Защита ключа** не меняется: ключи людей — в агенте токена, демо-персон — в `demo-signer`, системные — в томах; к ключу ГОСТ добавляется ключ ML-DSA-65 того же субъекта (регистрируется актом с доказательством владения).
- **Перешифрование** не нужно: подпись и шифрование — разные механизмы (AD-23); смена профиля подписи не трогает шифрование при хранении. Смена хеш-функции — отдельный сегмент цепочки (AD-32), не профиль подписи.
- **Понижение** (hybrid → gost, gost → pq) отвергается и как смена профиля, и как пакет: `signing.profile_downgrade`.
