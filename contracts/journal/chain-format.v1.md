# Формат цепочки журнала v1 (AD-44, AD-8, AD-23)

Схема записи — `entry.schema.json`. Открытые поля — заголовок записи; конверт DSSE с payload и подписями и `salt` — в зашифрованном блоке `sealed`.

## Формулы

```
H(x)        = Стрибог-256(x)                 — 32 байта в порядке hash.Sum() (GoGOST gost34112012256)
commit      = H( salt ‖ JCS(конверт DSSE) )   — salt: 16 случайных байт на запись
open_hash   = H( JCS(открытые поля записи без link) )
link        = H( prev_link ‖ commit ‖ open_hash )
```

- `‖` — склейка **сырых** байтов; `commit`, `link`, `prev_link` в формулах — по 32 байта (без префикса `streebog256:` и не hex).
- `prev_link` первой записи цепочки — 32 нулевых байта; дальше — `link` предыдущей записи **той же** цепочки (`main` или `ca`).
- «Открытые поля» — все поля записи из `entry.schema.json`, кроме `link` и `sealed`; отсутствующие необязательные поля опускаются (ключа нет), `null` — только где схема допускает null (`causation_id`, `supersedes`). `commit` входит в открытые поля.
- JCS — RFC 8785; строки `streebog256:‹hex›` входят в JCS как строки.
- В JSON и на экранах `commit`, `link`, отпечатки — `streebog256:` + 64 hex.

## Порядок записи

`journal.Append(пачка, критические_действия, ограждение, проверки)` — единственная функция записи; в одной транзакции: проверка аренды с эпохой (`journal.fenced`), блокировка головы основной цепочки, затем — если есть CA — цепочки CA, проверки AD-39 (`journal.stale_state`, `journal.stale_policy`, `journal.concession_exhausted`), вычисление звеньев, INSERT. `committed_at` и `recorded_at` не убывают по `seq` (`journal.time_regression`).

## Шифрование (AD-23)

`sealed` = AEAD(DEK, JCS(`plain_block`)), где `plain_block` = `{salt_b64, envelope}`; дополнительные данные AEAD = `chain ‖ seq ‖ commit` (ASCII `chain`, `seq` — 8 байт big-endian, `commit` — 32 байта). После расшифрования `commit` проверяется всегда. Открыты: заголовок, `commit`, звено; результат контроля и содержание решения — только в зашифрованном блоке (имена типов результат не кодируют).

## Контрольные точки (AD-8)

Хранитель принимает новую голову, только если звенья от прежней головы сходятся; точка — пакет DSSE класса `checkpoint` профиля `hybrid` (`contracts/crypto/checkpoint.schema.json`), головы обеих цепочек — в одной точке; первая точка каждой цепочки несёт отпечаток генезиса.

## Тест-вектор

`contracts/crypto/test-vectors/vectors.v1.json`, раздел `chain_v1`: две последовательные записи с `salt`, открытыми полями, `commit`, `open_fields_hash`, `prev_link`, `link`.

## Смена хеш-функции

Новая версия формата цепочки = новый сегмент: служебная запись `journal.segment.opened` связывает голову старого сегмента с перехешированием, хранитель подписывает её обоими профилями (AD-32).
