# «Главный» — платформа управления производством

«Главный» — доверенная система контроля качества изделий и решение кейса КосмоХакатона 2026 «Интеллектуальный контроль качества деталей в космической
отрасли». Имя — кодовое имя Главного конструктора. Техническое имя в коде — `ant` (`backend/cmd/ant`, переменные
`ANT_*`), репозиторий — `cosmos_hack`.

## Что это

Система для единичного и мелкосерийного производства ракетно-космической отрасли. Она собирает результаты
контроля, производственные события, действия исполнителей и состояние оборудования в единую подписанную историю
каждого экземпляра изделия, помогает рассмотреть несоответствие и разобрать его обстоятельства и не пускает
изделие через закрывающую точку без подписанного решения уполномоченного человека.

- **Машина ищет, человек решает.** Сигнал камеры или прибора — ещё не несоответствие. Автоматика изолирует,
  блокирует и расширяет область риска; «годно», «ремонт», «списать» ставит только человек с подписью.
- **Одна правда.** Всё, что система знает, — записи журнала, в который только дописывают; всё, что она
  показывает, пересчитывается из журнала. Исходный сигнал, вывод системы, решение человека и показатель различимы.
- **Подмену видно.** Записи сцеплены хешами Стрибог, контрольные точки подписывает отдельный хранитель
  гибридной подписью ГОСТ + ML-DSA-65, независимый верификатор переигрывает журнал.
- **Процесс — данные.** Маршрут и контроль описаны в BPMN 2.0 с расширениями; новая версия вступает в силу
  после подписей кворума. Столы ролей — тоже данные.
- **Обмен с учётными и производственными системами.** 1С и Галактика:ERP — за одним портом учёта, учётные
  последствия уходят на закрывающих точках; MES получает блоки ОТК и отдаёт задания и события операций;
  из КОМПАС-3D импортируется состав сборки; СКУД даёт присутствие на постах. Все — со stand-ами за протоколами
  настоящих систем; включает и переключает «стенд ↔ реальная» администратор на экране «Интеграции».

## Запуск одной командой

Нужен только Docker (Engine ≥ 24, Compose ≥ 2.29.7). Go и Node.js на машине не нужны: всё собирается в
контейнерах. В корне репозитория:

```sh
docker compose up
```

или то же в фоне с ожиданием готовности и со службой `demo-signer` (она подписывает шаги людей в режиме
«Автопроверка» тестовых сценариев; без неё работает режим «Интерактивно»):

```sh
make demo                          # = ANT_PROFILE=demo COMPOSE_PROFILES=demo docker compose up -d --wait
```

Первый запуск собирает образ (несколько минут), дальше старт занимает секунды. Во время работы система не
обращается в интернет: шрифты и иконки встроены, Go-зависимости лежат в `backend/vendor`, секреты (пароль БД,
ключи хранителя и верификатора, ключ шифрования при хранении) создаются в томах при первом запуске.

| Адрес | Что |
|---|---|
| <http://127.0.0.1:8480/> | интерфейс |
| <http://127.0.0.1:8480/healthz> | процесс жив |
| <http://127.0.0.1:8480/readyz> | самопроверка пройдена, БД отвечает |
| <http://127.0.0.1:8480/metrics> | метрики Prometheus |
| <http://127.0.0.1:8491/stand/1c/> | stand 1С: обмен «глазами 1С» (OData v3 + HTTP-сервис `/hs/qc/v1/`) |
| <http://127.0.0.1:8491/stand/galaktika/> | stand Галактики ERP: задания, партии, журнал обмена, документы Галактики |
| <http://127.0.0.1:8491/stand/mes/> | stand MES (B2MML-JSON): задания, операции, полученные блоки ОТК |
| <http://127.0.0.1:8491/stand/skud/> | stand СКУД: кнопки проходов, журнал проходов |

Stand-ы — эмуляторы кейса за протоколами настоящих систем, в профиле `demo` включены все; учётный обмен ведёт
1С, переключить на Галактику — `ANT_ERP_LEDGER=galaktika docker compose up -d`. Описание — [docs/integrations/](docs/integrations/README.md).

Порт и адрес меняются переменными: `ANT_HTTP_PORT=9000 ANT_HTTP_BIND=0.0.0.0 docker compose up`; порт stand-ов — `ANT_STANDS_PORT`. Профиль —
`ANT_PROFILE=fixtures | demo | load | prod` (по умолчанию `demo`; `fixtures` — интерфейс на мире заготовок).

При первом запуске разовая служба `init` делает генезис доверия: ключи в тома, блок генезиса в журнале, подписанный
ключом-якорем, и файлы ключей демо-персон в `.demo-keys/token-agent/` (для расширения подписи). Повтор ничего не
меняет; вручную — `make keys`.

Остановить — `docker compose down`; удалить вместе с данными — `docker compose down -v`.

### Сборка без сети

Чтобы собрать образ на машине без интернета, заранее на машине с сетью:

```sh
make npm-cache                     # npm-пакеты → frontend/.npm-cache
docker pull golang:1.27.1 node:24.21.0-slim postgres:18.6-alpine gcr.io/distroless/static-debian12:nonroot
```

## Как войти

На экране входа раскройте «Демо-вход: выберите сотрудника» — пароль не нужен (профили `demo` и `fixtures`).
Сотрудники — условные псевдонимы стартовой политики доступа.

| Роль | Демо-персона | Что открывается |
|---|---|---|
| Контролёр качества | INS-01 | очередь «Ждут моего решения», карточка несоответствия |
| Мастер участка | FOR-WC | участок, люди и оборудование, задачи, смена |
| Технолог | TEC-01 | разбор причин и обстоятельств, область риска, процесс |
| Руководитель производства | PM-01 | живая карта процесса, показатели, предложения |
| Администратор | ADM-01 | пульт тестовых сценариев и табло, доступ, источники, состояние |
| Начальник ОТК | HQC-01 | стол контролёра, адаптация VisionQC, партнёры и выписки |
| Исполнитель | W21 | терминал рабочего места |
| Представитель заказчика | CR-71 | «Требуется ваше решение» |
| Согласующий (держатель КД) | DA-81 | «Требуется ваше решение» |
| Аудитор ИБ | AUD-01 | целостность, журнал критических действий, события безопасности |

Главная демонстрация: ADM-01 → «Тестовые сценарии» → «Главная история «Плохой день сварочного участка (ИС-2)»» →
«Запустить сценарий»; справа — табло «ожидалось → получилось». Справка роли — кнопка «?» в шапке, работает офлайн.

### Подпись решений ключом

Закрывающие решения подписываются ключом человека через расширение браузера «Главный — подпись» (Chrome, Chromium,
Яндекс Браузер ≥ 116). Два способа за одним портом подписи: **ключ в браузере** — файл ключа загружается в расширение
и хранится там под PIN, подпись считает пакет WASM (на нём держится демо); **физический ключ** — у программы агента
токена, расширение только передаёт ей запрос (эталон, на который рассчитана система). Способ хранения ключа записан в
акте регистрации и виден в подписи, аудите и отчёте `make verify`.

1. `make token-agent` — пакет рабочего места (расширение с пакетом подписи WASM, агент токена под macOS и Linux,
   скрипт установки): архив `dist/glavny-token-agent-macos-arm64.tar.gz`. Папку `extension/` из репозитория напрямую
   не загружать — в ней нет пакета подписи.
2. Браузер → `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное расширение» →
   `dist/glavny-token-agent/extension`.
3. «Управление ключом» → «Файлы ключей» — файлы из `.demo-keys/token-agent/` (по два на каждую из 26 демо-персон:
   ГОСТ `ins-01-ta@1.key.json` и ML-DSA `ins-01-ta-pq@1.key.json`), PIN → «Загрузить и зашифровать». Разрешите адрес
   стенда (`http://127.0.0.1:8480`) кнопкой «Разрешить» и перезагрузите вкладку.

Демо-ключи в профилях `demo` и `fixtures` выводятся из публичного демо-зерна репозитория: одинаковы на любой машине
и после сброса стенда, загруженный однажды ключ не нужно перезагружать. Поэтому они не секрет и только для демо; в
`prod` такой вывод запрещён. Подробно, с неполадками, — [docs/guides/sign_extension.md](docs/guides/sign_extension.md).
Без расширения в демо-профиле решения подтверждаются кнопкой «Подтвердить без агента токена — демо» (в паспорте —
«подпись не проверялась»); там, где маршрут разрешает, — подпись на бумаге с QR и заверением второго сотрудника.

## Требования к машине

| Что | Сколько |
|---|---|
| ОС | Linux x86-64 (проверено на Ubuntu 22.04); macOS и Windows — через Docker Desktop |
| Docker | Engine ≥ 24, Compose ≥ 2.29.7 |
| Память | до 2,4 ГБ системе в работе (лимиты контейнеров); для первой сборки образа желательно 3 ГБ и больше |
| Диск | около 4 ГБ: базовые образы сборки, кэш, данные |
| Сеть | только для первой сборки (или заранее — см. «Сборка без сети»); во время работы не нужна |
| Браузер | Chromium или Firefox последних версий, ширина экрана от 1920 px — оптимально |

## Разработка

Все цели — `make help`. Главные:

| Цель | Что делает |
|---|---|
| `make up` / `make down` | поднять систему в фоне и дождаться готовности / остановить |
| `make build` | собрать образ `ant:local` |
| `make check` | все проверки: направление зависимостей, детерминизм домена, линтеры, тесты, фронтенд, GoGOST, контракты, кодогенерация, совместимость |
| `make generate` | перегенерировать производные файлы из контрактов |
| `make contract-demo` | ломающее изменение контракта обнаруживается до отправки в 1С |
| `make tamper` / `make verify` | подделка в обход системы и её обнаружение / независимая проверка журнала |
| `make sim-check` | генератор сценариев, потоки по схемам контракта, автосверка на заготовках |
| `make rebuild` | пересборка проекций из журнала |
| `make keys` | генезис доверия и ключи демо-персон (повтор ничего не меняет) |
| `make token-agent` | пакет рабочего места: расширение подписи + WASM + агент токена |
| `make load` | нагрузочный прогон 1 и N воркеров со сравнением хешей — только на выделенном стенде |
| `make dev-db` / `make run` | своя БД в общем dev-postgres / роль `api` из исходников против неё |
| `make licenses` | перечень зависимостей с лицензиями → `docs/licenses/` |

Проверка документации — `node docs/scripts/check-docs.mjs` (ссылки и якоря, руководства = встроенная справка,
пути в путеводителе, заголовки пакетов Go).

### Что проверяет `make check`

- **Слои (AD-1, NFR-ARCH-1, NFR-DEV-3).** `golangci-lint` + `depguard`: домен не импортирует
  приложение и инфраструктуру; доменные модули импортируют только модули раньше себя в порядке
  `reference → signing → access → item → process → vision → quality → machinelogs → documents →
  nonconformity → analysis → notifications → crossitem → engine`; зоны `storage`, `transport`,
  `integration`, `fixtures` не импортируют друг друга. Правила генерируются из
  `backend/tools/archgen/layers.json` в `backend/.golangci.yml`.
- **Детерминизм домена (AD-4, NFR-DET-1).** `forbidigo`: в `domain/**` нет `time.Now` и других
  часов, `math/rand`, `crypto/rand`, пакета `os`; анализатор `detcheck`: нет `float32/float64` и
  обхода `map` без сортировки.
- **Самопроверка.** В копии кода создаются пробные нарушения (импорт инфраструктуры из домена,
  `time.Now()` в домене, float и др.) — каждое должно быть поймано, иначе проверка красная.
- **Фронтенд.** ESLint запрещает ручные HTTP-вызовы (`fetch`, `axios` и т. п.) вне
  `src/shared/api/sse` — только сгенерированный клиент (AD-20); столы ↔ реестр виджетов ↔ политика; `vue-tsc`; тесты; сборка.
- **Контракты.** `contracts/scripts/check.sh`; сгенерированное не устарело; ломающие изменения против `contract-v1`.

### Структура

```text
backend/          Go-модуль ant: cmd/*, internal/{domain,application,infrastructure}/…
frontend/         Vue 3 + Vite + TypeScript + Naive UI, слои FSD
contracts/        единственные источники контрактов (AD-20)
normative/        нормативный слой: BPMN, карта реакций, политика, столы ролей, справочники
scenarios/        тестовые сценарии и ожидаемые результаты
extension/        браузерное расширение агента токена
deploy/           Dockerfile, compose, config/ant.yaml, k8s (манифесты Kubernetes), служебные скрипты
third_party/      заимствованный код исходниками (GoGOST)
docs/             документы для жюри и пользователей
```

### Конфигурация

`deploy/config/ant.yaml`: секция `defaults`, поверх неё — `profiles.<профиль>`, поверх —
переменные `ANT_*` (путь ключа через `_`: `http.addr` → `ANT_HTTP_ADDR`). Секретов в переменных
нет: пароль БД и ключи — только файлами (`ANT_DB_PASSWORD_FILE`).
