# Словарь терминов документации

Единый словарь для интерфейса, документации и презентации (NFR-UI-3). Правило: в интерфейсе и документации — русский термин; английский — технический синоним в API, коде, при ссылке на международный стандарт и в скобках при первом упоминании редкого термина. Код, идентификаторы и ключи контрактов — латиница (соглашение «Язык» спайна).

Пример: «Прохождение контроля с первого раза (FPY)», а не «FPY».

## 1. Главные различия — нельзя смешивать

- **Признак дефекта** (что заметила автоматика) ≠ **подтверждённое несоответствие** (решил уполномоченный) ≠ **гипотеза причины** ≠ **подтверждённая причина** / **подтверждённая ошибка исполнителя** (кейс §2.3).
- **Под подозрением** ≠ **несоответствие**. **Заблокировано** ≠ **признано дефектным**. **Оценка невозможна** ≠ **годно**. **Уверенность анализатора** ≠ вероятность брака (NFR-UI-4).
- **Переделка** (возврат к исходным требованиям) ≠ **ремонт** (приемлемо для использования, но не обязательно соответствует требованиям).
- **Разрешение на отклонение** (для уже изготовленного изделия: ремонт, «как есть») ≠ **разрешение на отступление** (выдаётся до изготовления) — ГОСТ Р ИСО 9000-2015, пп. 3.12.5, 3.12.6.
- **Коррекция** (устранить конкретное несоответствие) ≠ **корректирующее действие** (устранить причину) ≠ **сдерживание** (временные защитные меры).
- **Внедрено** ≠ **результативно**; **исполнено** ≠ **проверено**.
- **Дефект** — конкретное отклонение изделия; **несоответствие** — невыполнение требования; **изделие с несоответствием** — изделие, у которого подтверждено хотя бы одно несоответствие. Три дефекта на одной детали — одно изделие с несоответствием.
- **Брак** — отраслевой термин (ГОСТ 15467, «акт о браке») для **итога по изделию**: исправимый брак → переделка, неисправимый → списание. Не синоним сигнала или подозрения. Изделие, принятое по разрешению на отклонение, браком не является.
- **Изоляция** — положение изделия, ждущего решения; **блок** — уровень сдерживания, запрещающий движение; снятие блока ≠ годность.

## 2. Изделие и процесс

| Термин | Синоним (англ.) | Значение |
|---|---|---|
| Изделие (экземпляр) | Item / Item Instance | конкретная физическая единица с уникальным идентификатором; «деталь» в интерфейсе — синоним для экземпляра детали |
| Тип изделия | Item Type | модель или семейство |
| Компонент | Component | составная часть изделия |
| Закрывающая точка (ЗТ) | Closing Gate | точка маршрута, где изделие не идёт дальше без решения человека с подписью (в том числе точки предъявления ОТК и ПЗ / ВП) |
| Точка предъявления | Hold Point / Presentation Point | обязательное предъявление изделия ОТК или представителю заказчика; частный случай закрывающей точки |
| Исполнитель (оператор) | Operator | рабочий, выполняющий операцию; в интерфейсе — «исполнитель», в событиях — `operator` |
| Операция | Operation | этап работы по техпроцессу |
| Выполнение операции | Operation Run | конкретное выполнение над конкретным изделием; повтор — новое выполнение со ссылкой на прежнее |
| Участок, смена | Station, Shift | — |
| Линия | Production Line | поток, по которому идут изделия одного типа; поле `line_id` |
| Цех | Workshop | производственное подразделение со своим складом; в процессе — дорожка BPMN; передача между цехами — смена склада, сообщается в 1С |
| Предприятие | Enterprise | юридическое лицо кооперации со своей системой; предприятия связаны федерацией |
| Оборудование, инструмент, оснастка | Equipment, Tool, Fixture | — |
| Технологический маршрут | Routing | последовательность операций |
| Технологический шаг | Process Step | требуемое действие внутри операции |
| Зона | Zone | объект внутри изделия (участок шва, соединение, отверстие), к которому привязываются контроль, доработки, скрытые работы, вмешательства |
| Сопроводительная карта | Traveler | документ, который идёт с изделием по цеху; у нас собирается из истории |
| Цифровой паспорт изделия | Digital Product Passport | идентификатор экземпляра и связанная с ним полная подписанная история; журнал изменений паспорта |
| Выписка паспорта | Passport Extract | подписанный пакет ключевых сведений паспорта изделия или партии, передаваемый при отгрузке; цифровая замена бумажного сертификата качества |
| Носитель идентификатора | Carrier | бирка с QR, DPM DataMatrix, тара с ячейкой, сопроводительная карта, контекст поста, ручной ввод; отделён от идентичности изделия (AD-16) |
| Привязка | Binding | способ и надёжность связи события с изделием и операцией |

## 3. Контроль и наблюдения

| Термин | Синоним | Значение |
|---|---|---|
| Контроль | Inspection | проверка изделия, процесса или операции |
| Точка контроля (КТ) | Control Point | место и момент контроля в маршруте; в коде — `inspection_point` |
| Карта контроля | Inspection Recipe | что проверять, каким методом, при каком свете, что ловит и что нет, что делать с результатом; «карта», а не «сценарий» или «рецепт» |
| Метод контроля | Inspection Method | визуальный, измерительный (КИМ), рентген (РК), УЗК и т. п.; несёт перечень видов дефектов, которые способен выявить |
| Наблюдение, результат контроля | Observation, Inspection Result | факт наблюдения или измерения и его итог |
| Признак дефекта / признаки не обнаружены / оценка невозможна | Defect Indication / No Defect Indication / Unassessable | три исхода результата контроля (кейс §1.4) |
| Качество наблюдения | Observation Quality | пригодность данных |
| Уверенность анализатора | Analyzer Confidence | уверенность в интерпретации; отдельно от качества наблюдения |
| Подтверждающие материалы | Evidence | фото, измерения, журналы и т. п. |
| Сравнение до и после операции | Before / After | — |
| Дополнительный контроль | Additional Inspection | проверка, назначенная для недостающих данных |
| Вид дефекта | Defect Type | код классификатора дефектов (код, наименование, класс тяжести по ГОСТ 15467) |
| Паспорт допуска карты контроля | Inspection Qualification Record | утверждённая конфигурация контура контроля (изделие, операция, точка, камера, свет, калибровка, карта, анализатор, порог, классы) с разрешёнными и запрещёнными автоматическими действиями |
| Уровень доверия | Trust Level | какие действия анализатор может выполнять сам по паспорту: 0 — только запись … 4 — подтверждение заранее оговорённых безопасных результатов по правилу |
| Автоматизированный контроль | — | машина ищет, человек решает (ГОСТ 16504); не «автоматический» |

## 4. Статусы изделия

| Статус | Синоним | Значение |
|---|---|---|
| В работе | IN_PROCESS | идёт по маршруту |
| Под подозрением | SUSPECT | есть основания, несоответствие не подтверждено |
| Ожидает доп. контроля | REINSPECTION_REQUIRED | нужны данные |
| Заблокировано | HOLD | движение временно запрещено |
| Ожидает решения | PENDING_DECISION | нужно решение уполномоченного |
| Несоответствие подтверждено | NONCONFORMING | — |
| Исключено из подозрения | CLEARED | — |
| Разрешено к движению | RELEASED | — |
| На переделке / на ремонте | REWORK / REPAIR | — |
| Годно по разрешению на отклонение | ACCEPTED_WITH_CONCESSION | ≠ «годно» |
| Списано / возвращено поставщику | SCRAP / RETURNED | — |

Полная модель статусов по осям (положение, качество, решение, сдерживание, учёт в 1С, статус в инциденте) — [data-model.md](data-model.md), раздел 6.

## 5. Решения и действия

| Термин | Синоним | Значение |
|---|---|---|
| Решение по изделию | Disposition | переделка / ремонт / использовать как есть / списать / вернуть поставщику |
| Разрешение на отклонение | Concession | см. раздел 1 |
| Разрешение на отступление | Deviation Permit | см. раздел 1 |
| Коррекция | Correction | — |
| Сдерживание (временные защитные меры) | Containment | наблюдать / доп. проверка / блок изделий / блок партии / стоп точки процесса / критическая остановка |
| Область риска | Impact Scope / Suspect Population | изделия, которые могли подвергнуться той же причине; синоним — «зона возможного влияния» |
| Расширение / сужение области | Scope Expansion / Reduction | каждое — с основанием |
| Корректирующее / предупреждающее действие | Corrective / Preventive Action | — |
| Полномочие на решение, правило полномочий, делегирование | Decision Authority, Authority Policy, Delegation | — |
| Автоматически по утверждённому правилу, предложение решения, совместное согласование, внешнее согласование | Auto by Approved Rule, Proposed Decision, Multi-approval, External Authority | режимы автоматизации 2–5 (FR-50) |

## 6. Причины и улучшения

| Термин | Синоним | Значение |
|---|---|---|
| Анализ причин / анализ корневой причины | Cause Analysis / RCA | — |
| Гипотеза причины / подтверждённая причина | Cause Hypothesis / Validated Cause | — |
| Причина возникновения / причина пропуска контроля | Why Made / Why Missed | «почему возник» / «почему пропустили» |
| Сопутствующее обстоятельство | Contributing Factor | — |
| Окно возможного возникновения | Causal Window | от последнего подтверждённо нормального состояния до обнаружения |
| Повторное возникновение | Recurrence | — |
| План проверки результативности | Effectiveness Contract | условия, по которым проверяем, что мера сработала |
| Период усиленного контроля | Enhanced Monitoring | — |
| Результативно / нерезультативно | EFFECTIVE / FAILED | — |
| Инцидент | Incident | связанная группа сигналов и несоответствий с общей предполагаемой причиной |
| Предложение | Suggestion | запись генератора предложений с основаниями и ответственным; ничего не применяет само |
| Карта дефицита данных | Data Gap Map | сводка недостающих сведений по расследованиям с оценкой, какая цифровизация сузила бы область риска (FR-143) |

**Запрещённая логика:** «исполнитель работал с изделием → исполнитель причина». **Допустимая:** «действие исполнителя входит в окно возможного возникновения → одно из обстоятельств».

## 7. Контроль действий оператора

| Термин | Синоним | Значение |
|---|---|---|
| Контроль действий оператора | OperatorVision | имя модуля в интерфейсе |
| Контроль соблюдения техпроцесса | Process Execution Verification | ожидаемая последовательность ↔ наблюдаемая |
| Отклонение от техпроцесса, пропущенный шаг, нарушение последовательности, ручное вмешательство | Process Deviation, Missed Step, Sequence Break, Manual Intervention | до подтверждения — «наблюдаемое событие», а не «ошибка» |
| Учёт инструмента | Tool Accountability | все инструменты, вошедшие в зону, вышли |
| Подтверждённая ошибка исполнителя | Confirmed Operator Error | только после расследования, решения уполномоченного и объяснения работника (ТК РФ ст. 247) |

## 8. Оборудование и критические действия

| Термин | Синоним | Значение |
|---|---|---|
| Профиль выполнения операции | Operation Run Profile | собранный контекст одного выполнения: изделие, станок, программа и ревизия, инструмент и его ресурс, оснастка, начало и конец, режим, ручные изменения, предупреждения и отклонения, контроль до и после (FR-148) |
| Измерение / событие / состояние оборудования | Sample / Event / Condition (MTConnect) | непрерывная величина / смена дискретного состояния / исправность (норма, предупреждение, неисправность) |
| Ресурс инструмента | Tool Life | сколько циклов сделано из допустимых (например, 73 из 75) |
| Ручное изменение режима | Manual Override | например, подача 130 % от программы; обстоятельство, а не вина |
| Последнее подтверждённо нормальное состояние | Last Known Good | нижняя граница окна возможного возникновения и области риска |
| Специальный процесс | Special Process | процесс, результат которого нельзя оценить последующим контролем (ГОСТ Р 58633-2020, п. 3.17); нарушение режима — само по себе несоответствие (FR-151) |
| Критическое действие | Critical Action | действие, меняющее судьбу изделия или процесса, официальное заключение о качестве, полномочия или защищённую настройку контроля |
| Цифровое клеймо | Acceptance Authority Media (IAQG) | личное подтверждение уполномоченного лица — электронный аналог клейма ОТК; в документах — «цифровое клеймо контролёра» |
| Источник факта | Source Kind | откуда пришёл факт (ручной ввод / станок / датчик / камера / внешняя система / импорт) и насколько он надёжен (FR-140) |

## 11. Роли

- **Пять ролей кейса:** контролёр качества, мастер участка, технолог, руководитель производства, администратор.
- **Дополнительные роли той же политикой:** исполнитель (только своё рабочее место), представитель заказчика (ВП / ПЗ), согласующий (конструктор или держатель КД, метролог, член комиссии по качеству), Аудитор ИБ.
- **Руководящие подписанты** — роли-наследники базовых: начальник ОТК ⊃ контролёр качества, начальник цеха, главный конструктор и т. п.
- **Полномочие** — особое право конкретного человека поверх роли с рамками (программа, семейство изделий, тяжесть, типы решений, область) и сроком.
- **Участники без роли:** устройства (edge-агент камеры, станок, шлюз) подписывают свои сообщения ключом устройства.

## 12. Архитектурные термины

| Термин | В коде | Определение | Опора |
|---|---|---|---|
| Журнал | `journal` | неизменяемый журнал всех записей; единственный источник истины; только дописывание | AD-2, FR-71 |
| Запись журнала | entry | одна позиция журнала с открытыми полями, зашифрованным конвертом и звеном цепочки | AD-44 |
| Факт / реакция / решение / служебная запись | `entry_kind`: `fact` / `reaction` / `decision` / `service` | сообщение источника / что сделал движок / решение человека с подписью / время, политика, ключи, контрольные точки, генезис, карантин | AD-2 |
| Проекция | projection | таблица для чтения, пересобираемая из журнала; один писатель | AD-45 |
| Свёртка и пересвёртка | fold | чистая функция «версия процесса + вход изделия → состояние + реакции»; на каждое новое событие изделие сворачивается заново целиком | AD-5, AD-40 |
| Слот реакции | `reaction_slot` | (правило, субъект, ключ срабатывания); пересмотр — следующая версия того же слота | AD-3 |
| Межизделийная стадия | `crossitem` | расчёты над несколькими изделиями: генеалогия, партии, оборудование, область риска, привязка событий без изделия | AD-42 |
| Партиция и аренда | partition, lease | фиксированная доля изделий по `hash(item_id) mod P`; право воркера обрабатывать её, с эпохой | AD-6 |
| Хеш-цепочка | chain | звено каждой записи зависит от предыдущего; две цепочки — основная и критических действий | AD-8, AD-44 |
| Контрольная точка | `checkpoint` | подписанная хранителем голова цепочек; не путать с точкой контроля процесса | AD-8 |
| Хранитель | `keeper` | отдельный процесс, который принимает головы цепочек, только если цепочка продолжена, и подписывает контрольные точки | AD-8 |
| Верификатор | `verifier` | независимая программа только на чтение, переигрывающая журнал и проверяющая цепочки, подписи, права и правила | AD-9, FR-73 |
| Генезис | genesis | первые записи журнала, подписанные якорем доверия: профили, системные ключи, стартовая политика, справочники, нормативный слой v1 | AD-33 |
| Якорь доверия | anchor | установочный ключ, подписывающий генезис и уничтожаемый сразу после | AD-33 |
| trust-anchors | `trust-anchors` | файл с отпечатками якоря, хранителя, верификатора и генезиса вне БД и вне `ant` | AD-33 |
| Криптопрофиль | `gost` / `pq` / `hybrid` | ГОСТ Р 34.10-2012 со Стрибогом / ML-DSA-65 (демонстрационный) / обе подписи обязательны | AD-10, AD-32 |

## 13. Слова, которых избегаем

| Не так | Так |
|---|---|
| «ИИ нашёл брак» | «Обнаружен признак дефекта» |

- Статусы раздела 4 — термины кейса с английскими синонимами, а не коды.
