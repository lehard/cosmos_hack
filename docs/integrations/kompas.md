# Интеграция с КОМПАС-3D

Импорт структуры сборки из КОМПАС-3D (FR-94, кейс §3.3, §5.3): в MVP — импорт **файла условной сборки** (идентификатор, версия, компоненты, количество, связи; отсутствие геометрии обозначено явно); прямое подключение через программный интерфейс САПР или через PLM — описание пути перехода.

**Опоры:** FR-90, FR-94, FR-95, FR-45, FR-46, FR-18, FR-20; AD-17, AD-18, AD-31; PRD §11.15; кейс §3.3, §5.3; критерии Т2, О5. Общие правила — [README.md](README.md).

## 1. Направления и данные

| Направление | Данные | Шаг процесса |
|---|---|---|
| КОМПАС-3D / PLM → `ant` | состав сборки: обозначение, версия КД, литера, позиции (детали, сборочные единицы, покупные, стандартные изделия), количество, учёт по партиям или заводским номерам, связи, важные характеристики с методами контроля | нормативный слой: до запуска изделий; новая версия состава действует только для изделий, запущенных после неё (AD-17) |
| `ant` → КОМПАС-3D | ничего | — |

Обратного потока нет: конструкторские данные — зона PLM/САПР; `ant` их только читает. Расхождения (обозначение из КОМПАС не совпало с номенклатурой 1С) — отчёт о расхождениях администратору и технологу, без автосоздания.

**Что делает импорт.** Файл проходит обычный приём как источник `cad:kompas` (`source_kind` — импорт): схема, идемпотентность по хешу файла, карантин с кодом при ошибке. Модуль `cad` превращает его в **новую версию состава** в нормативном слое; прежняя версия не правится (кейс §4.6, FR-22). Связи переводятся в объекты нормативного слоя (§4). Изделия, уже запущенные по прежней версии, доделываются по ней.

## 2. Шаг процесса и связь с маршрутом фланца

Демо-изделие — **фланец люка гермокорпуса в сборе ФЛ-100.00.000 СБ** (PRD §11.15). Состав определяет:

- какие компоненты проходят входной контроль (ЗТ-1) и как учитываются: по партиям (крепёж, уплотнение) или по заводским номерам (фланец);
- генеалогию «изделие ← детали» при сборке (FR-45) — её ведёт межизделийная стадия (AD-42);
- зоны изделия (FR-46), к которым привязаны контроль, доработки, скрытые работы и вмешательства;
- ограничения шагов сварки (ЗТ-3) и сборки (ЗТ-4).

## 3. Формат файла условной сборки

Схема — `contracts/integrations/cad/assembly.schema.json` (AD-18). Ниже — пример для ФЛ-100.00.000 СБ, версия «Б», литера О1. **Все значения — проектные допущения** (обозначения компонентов, материалы, характеристики условные; эталонный файл — в `contracts/integrations/cad/examples/`, путь предварительный).

```json
{
  "format": "ant.cad.assembly",
  "format_version": 1,
  "source": {
    "kind": "manual",
    "system": "КОМПАС-3D",
    "file": "ФЛ-100.00.000СБ.a3d",
    "extracted_at": "2026-09-25T06:00:00.000Z",
    "extractor": "ручная подготовка по КД"
  },
  "assembly": {
    "designation": "ФЛ-100.00.000 СБ",
    "name": "Фланец люка гермокорпуса в сборе",
    "kd_revision": "Б",
    "litera": "О1",
    "geometry": null,
    "geometry_note": "Файл подготовлен без выгрузки из САПР; геометрия не передаётся и системе не нужна"
  },
  "components": [
    {"ref": "p1", "designation": "ФЛ-100.00.001", "name": "Фланец", "kind": "part", "qty": 1, "unit": "шт", "material": "АМг6", "tracking": "serial"},
    {"ref": "p2", "designation": "ПТ-40-01", "name": "Патрубок (покупной)", "kind": "purchased", "qty": 1, "unit": "шт", "tracking": "serial"},
    {"ref": "p3", "designation": "ФЛ-100.00.002", "name": "Крышка", "kind": "part", "qty": 1, "unit": "шт", "material": "АМг6", "tracking": "serial"},
    {"ref": "p4", "designation": "ФЛ-100.00.003", "name": "Уплотнение", "kind": "part", "qty": 1, "unit": "шт", "tracking": "lot", "shelf_life_days": 365},
    {"ref": "p5", "designation": "Болт М8-6g×25 ГОСТ 7798-70", "name": "Болт", "kind": "standard", "qty": 12, "unit": "шт", "tracking": "lot"},
    {"ref": "p6", "designation": "Шайба 8 ГОСТ 11371-78", "name": "Шайба", "kind": "standard", "qty": 12, "unit": "шт", "tracking": "lot"}
  ],
  "relations": [
    {"id": "W-1", "kind": "weld", "joins": ["p1", "p2"], "zone": "шов W-1", "rework_limit": 3},
    {"id": "J-1", "kind": "bolted_joint", "joins": ["p1", "p3", "p5", "p6"], "zone": "болтовое соединение J-1", "closes_access_to": ["S-1", "внутренняя поверхность фланца"]},
    {"id": "S-1", "kind": "seal", "joins": ["p4", "p1"], "zone": "уплотнение S-1", "install_before": ["p3"]}
  ],
  "key_characteristics": [
    {"id": "KC-1", "zone": "шов W-1", "name": "Отсутствие трещин и непроваров", "methods": ["визуальный автоматизированный", "рентгеновский"]},
    {"id": "KC-2", "zone": "уплотнительная поверхность фланца", "name": "Плоскостность", "tolerance": "0,05 мм", "methods": ["измерительный (КИМ)"]},
    {"id": "KC-3", "zone": "изделие в сборе", "name": "Герметичность", "methods": ["испытание на стенде с течеискателем"]}
  ],
  "external_ids": {"onec_nomenclature_key": null},
  "checksum": {"alg": "streebog256", "value": "…"}
}
```

Правила формата:

- `geometry: null` — **явно**, с пояснением (кейс §5.3); пропущенное поле — ошибка схемы, а не «геометрии нет».
- `designation` (+ исполнение) — естественный ключ позиции; пустое обозначение — ошибка импорта, а не новая деталь.
- `kd_revision` обязательна: изделие исполняется по версии, действовавшей при его запуске.
- Повторный импорт того же файла (тот же хеш) — дубль; изменённый файл — новая версия состава.

## 4. Связи → объекты нормативного слоя

Связи сборки не остаются «картинкой»: модуль `cad` переводит их в зоны и ограничения, которые исполняет движок (AD-18):

| Связь | Что это | Что появляется в нормативном слое | Какое правило срабатывает |
|---|---|---|---|
| W-1 | сварной шов фланца с патрубком | зона изделия «шов W-1» — объект учёта **лимита ремонтов** | петля доработки с лимитом (FR-18): четвёртая доработка шва при лимите 3 без отдельного разрешения блокируется |
| J-1 | болтовое соединение крышки | зона «болтовое соединение J-1» со свойством **«закрывает доступ к зоне»** | скрытые работы (FR-20): начать установку крышки без завершённой проверки закрываемой зоны нельзя; разборка — запись вмешательства (FR-21) |
| S-1 | уплотнение | зона «уплотнение S-1» и **порядок установки** «до крышки»; срок хранения партии уплотнений | предусловие операции (FR-17): просроченная партия или нарушенный порядок — блокировка |

Важные характеристики `key_characteristics` сопоставляются с методами контроля и покрытием видов дефектов (FR-14) в плане контроля версии процесса. Импорт даёт **черновик** изменений нормативного слоя; действующим он становится только после утверждения кворумом (FR-23).

## 5. Источник достоверных сведений и сопоставление идентификаторов

- Источник истины по конструкторскому составу, обозначению, исполнению и версии КД — КОМПАС-3D / PLM. Источник истины по учётной карточке номенклатуры — ERP.
- Внешний ID позиции — обозначение (+ исполнение) + имя файла + хеш файла; `UniqueNum` КОМПАС уникален только внутри документа и ключом не служит.
- **Правило сопоставления с 1С** (проектное предположение): позиция состава связывается с номенклатурой 1С по обозначению по ЕСКД (в 1С — реквизит номенклатуры, где хранится обозначение, например «Артикул»; сверяется по `$metadata`). Найдено одно совпадение — две записи `reference.external_id.mapped` (КОМПАС и 1С) указывают на один наш тип изделия. Не найдено или найдено несколько — отчёт о расхождениях, без автосоздания номенклатуры. Промышленный путь — сквозной MDM-идентификатор (ПОЛИНОМ:MDM / ЛОЦМАН:PLM), тогда сопоставление идёт по нему.
- Если в файле уже есть ссылка на номенклатуру 1С (`external_ids.onec_nomenclature_key`), она проверяется, а не принимается на веру: расхождение с обозначением — сигнал.

## 6. Ошибки импорта

| Ошибка | Поведение |
|---|---|
| файл не проходит схему (нет `geometry`, нет `kd_revision`, пустое обозначение) | карантин приёма с кодом и указанием поля (FR-30) |
| неизвестная `format_version` | карантин с кодом «неизвестная версия»; переобработка после появления повышателя (AD-20) |
| тот же файл повторно | дубль, ничего не меняется (FR-31) |
| ссылка связи на несуществующую позицию | карантин с кодом и `id` связи |
| позиция не сопоставлена с номенклатурой ERP | версия состава принимается, позиция помечена «нет соответствия», отчёт о расхождениях и задача администратору |
| конфликт соответствия ID | сигнал, без перезаписи (AD-18) |

## 7. Путь к прямому подключению

Программный интерфейс КОМПАС-3D — **COM (API5 и API7)**, только под Windows при установленном и лицензированном КОМПАС (проверено по документации SDK). Штатного экспорта состава изделия в XML нет — только геометрия (STEP AP203/214/242, JT и др.), поэтому файл условной сборки — наш формат.

1. **Экстрактор через COM API7** (ближний шаг): небольшая программа на рабочем месте конструктора или на Windows-шлюзе открывает сборку только на чтение (`Kompas.Application.7` → документ → `TopPart`), обходит уникальные компоненты (`IPart7.PartsEx`), берёт обозначение (`Marking`), признаки «деталь / стандартное изделие» (`Detail`, `Standard`), материал, массу, количество вхождений (`GetInstanceCount`) и формирует тот же файл с `source.kind = "kompas-api7"`. Связи и важные характеристики берутся из атрибутов модели или дописываются технологом. Windows-шлюз — отдельный узел со своим ключом устройства, файл идёт в `ant` через edge-агент как подписанный факт.
2. **ЛОЦМАН:PLM** (промышленный путь): в промышленности КОМПАС → ERP идёт через PDM, а не из САПР. Адаптер подписывается на изменённые объекты через интеграционную шину ЛОЦМАН (XML: описательная часть + объекты с атрибутами и связями) или SDK сервера приложений; ID — идентификатор объекта ЛОЦМАН + номер версии, связь с 1С — через MDM-идентификатор. Серверная часть ЛОЦМАН работает под Linux.

В обоих случаях меняется только адаптер `infrastructure/integration/cad/‹источник›`; формат для ядра и правила нормативного слоя — те же.

## 8. Смежный узел: САПР ТП ВЕРТИКАЛЬ (описание, критерий О5)

САПР ТП ВЕРТИКАЛЬ (АСКОН) штатно экспортирует техпроцесс в XML «с учётом структуры и связей» и содержит **контрольные операции**, **контролируемые параметры** (передаются в контрольную операцию из предшествующих операций) и **режимы контроля**, созданные по маркерам чертежа КОМПАС (проверено по руководству пользователя). Это готовый источник контрольных точек и характеристик для **черновика** версии процесса:

| ВЕРТИКАЛЬ | Черновик BPMN `ant` |
|---|---|
| межцеховой маршрут | дорожки цехов, шаги перемещения |
| операция (цех, оборудование, норма времени) | задача BPMN со свойствами `urn:ant:bpmn-ext:1` (норма, цех) |
| контрольная операция | задача контроля человеком — точка предъявления |
| контролируемый параметр, режим контроля | характеристика с допуском и методом в плане контроля |

Результат — только черновик: действующей версию делает утверждение кворумом (FR-23). Схема XML ВЕРТИКАЛИ не проверена (нужен образец файла) — это **описание, не MVP**.

## 9. Граница эмуляции (NFR-TEST-2)

Эмулятора КОМПАС нет и он не нужен: кейс допускает файл условной структуры (§3.3). В MVP — импорт файла ФЛ-100.00.000 СБ через обычный приём; экстрактор COM API7 и адаптер ЛОЦМАН — описание.

**Где в коде:** `backend/internal/infrastructure/integration/cad/kompas/` (импорт файла), `backend/internal/domain/cad/` (перевод связей в объекты нормативного слоя), схема — `contracts/integrations/cad/assembly.schema.json`.

## Уточнить после появления кода

- Окончательные поля схемы `assembly.schema.json` (имена `format`, `format_version`, `tracking`, `relations[].kind`, `key_characteristics`) и эталонный файл фланца.
- Имя типа события импорта состава (семейство `cad`) и событий расхождений (`contracts/events/catalog.yaml`).
- Как связи W-1, J-1, S-1 представлены в свойствах `urn:ant:bpmn-ext:1` (`contracts/bpmn-ext/`).
- Реквизит номенклатуры 1С, по которому идёт сопоставление обозначения.
- Путь импорта файла (каталог, операция API или форма на столе технолога / администратора).
- Коды ошибок импорта в `contracts/errors.yaml`.
