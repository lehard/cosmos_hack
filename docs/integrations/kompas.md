# Интеграция с КОМПАС-3D

Импорт структуры сборки из КОМПАС-3D (FR-94, кейс §3.3, §5.3): в MVP — импорт **файла условной сборки** (идентификатор, версия, компоненты, количество, связи; отсутствие геометрии обозначено явно); прямое подключение через программный интерфейс САПР или через PLM — описание пути перехода.

**Опоры:** FR-90, FR-94, FR-95, FR-45, FR-46, FR-18, FR-20; AD-17, AD-18, AD-31; PRD §11.15; кейс §3.3, §5.3; критерии Т2, О5. Общие правила — [README.md](README.md).

## 1. Направления и данные

| Направление | Данные | Шаг процесса |
|---|---|---|
| КОМПАС-3D / PLM → `ant` | состав сборки: обозначение, версия КД, литера, позиции (детали, сборочные единицы, покупные, стандартные изделия), количество, учёт по партиям или заводским номерам, связи, важные характеристики с методами контроля | нормативный слой: до запуска изделий; новая версия состава действует только для изделий, запущенных после неё (AD-17) |
| `ant` → КОМПАС-3D | ничего | — |

Обратного потока нет: конструкторские данные — зона PLM/САПР; `ant` их только читает. Расхождения (обозначение из КОМПАС не совпало с номенклатурой 1С) — отчёт о расхождениях администратору и технологу, без автосоздания.

**Что делает импорт.** Файл загружает технолог или администратор (операция `cad.assembly.import`): адаптер проверяет его схемой и версией формата (ошибка — отказ с полем), домен `cad` переводит сборку, факты идут через обычный приём как источник `cad.kompas` (`source_kind` — импорт) с идемпотентностью по отпечатку файла. Модуль `cad` превращает его в **новую версию состава** в нормативном слое; прежняя версия не правится (кейс §4.6, FR-22). Связи переводятся в объекты нормативного слоя (§4). Изделия, уже запущенные по прежней версии, доделываются по ней.

## 2. Шаг процесса и связь с маршрутом фланца

Демо-изделие — **фланец люка гермокорпуса в сборе ФЛ-100.00.000 СБ** (PRD §11.15). Состав определяет:

- какие компоненты проходят входной контроль (ЗТ-1) и как учитываются: по партиям (крепёж, уплотнение) или по заводским номерам (фланец);
- генеалогию «изделие ← детали» при сборке (FR-45) — её ведёт межизделийная стадия (AD-42);
- зоны изделия (FR-46), к которым привязаны контроль, доработки, скрытые работы и вмешательства;
- ограничения шагов сварки (ЗТ-3) и сборки (ЗТ-4).

## 3. Формат файла условной сборки

Схема — `contracts/integrations/cad/assembly.schema.json` (AD-18), эталон — `contracts/integrations/cad/examples/kompas-assembly-flange.json`: файл процессной сессии (PRD §11.15) без изменений — ФЛ-100.00.000 СБ, версия «Б», литера О1, 7 позиций (фланец, патрубок, крышка люка — сборочная единица с клапаном КВД-6, уплотнение со сроком хранения, болты ×12 и шайбы ×12 с партиями), связи W-1, J-1, S-1 и резьбовое соединение J-2, 4 важные характеристики. **Все значения — проектные допущения.** Сокращённо:

```json
{
  "format_version": "1.0",
  "source": {"system": "КОМПАС-3D (эмуляция файлом)", "export_kind": "assembly_structure", "exported_at": "2026-09-21T08:00:00+03:00"},
  "assembly": {
    "assembly_id": "FL-100.00.000", "designation": "ФЛ-100.00.000 СБ", "name": "Фланец люка гермокорпуса в сборе",
    "version": "Б", "lifecycle_letter": "О1",
    "geometry": null, "geometry_note": "Геометрия отсутствует: для прототипа передаётся только состав, количества и связи.",
    "critical_characteristics": [{"id": "CC-1", "name": "Сварной шов фланца с патрубком, категория I", "control": ["камера (КТ-3)", "рентген"]}]
  },
  "components": [
    {"position": 1, "designation": "ФЛ-100.01.001", "name": "Фланец", "kind": "detail", "qty": 1, "make_or_buy": "make", "parent": "FL-100.00.000", "geometry": null},
    {"position": 5, "designation": "Болт М6×20 [П]", "name": "Болт крепления крышки", "kind": "fastener", "qty": 12, "lot_tracked": true, "parent": "FL-100.00.000", "geometry": null},
    {"position": 7, "designation": "КВД-6 [ПП]", "name": "Клапан выравнивания давления", "kind": "purchased_equipment", "qty": 1, "serial_tracked": true, "parent": "ФЛ-100.02.000", "geometry": null}
  ],
  "links": [
    {"type": "weld", "id": "W-1", "from": "ФЛ-100.01.001", "to": "ФЛ-100.01.002"},
    {"type": "bolted_joint", "id": "J-1", "from": "ФЛ-100.02.000", "to": "ФЛ-100.01.001", "fasteners": ["Болт М6×20 [П]", "Шайба 6 [П]"], "qty": 12, "tightening_sequence": "крест-накрест [П]"},
    {"type": "seal", "id": "S-1", "between": ["ФЛ-100.02.000", "ФЛ-100.01.001"], "part": "ФЛ-100.00.004"},
    {"type": "threaded_joint", "id": "J-2", "from": "КВД-6 [ПП]", "to": "ФЛ-100.02.000", "torque_nm": 12.0, "tolerance_pct": 10, "locking": "контровка проволокой"}
  ],
  "id_mapping_hint": {"rule": "обозначение КД + версия → внутренний item_type_id", "conflict_behavior": "несовпадение с номенклатурой 1С → отчёт о расхождениях, без автоматического создания"}
}
```

Правила формата:

- `geometry: null` — **явно**, у сборки и у каждой позиции, с пояснением `geometry_note` (кейс §5.3); пропущенное поле — ошибка схемы, а не «геометрии нет».
- `designation` — естественный ключ позиции; пустое обозначение — ошибка импорта, а не новая деталь. Дерево состава — через `parent` (идентификатор сборки или обозначение сборочной единицы); цикл или неизвестный родитель — ошибка.
- `version` обязательна: изделие исполняется по версии, действовавшей при его запуске.
- Числа — целые (AD-4): `12.0` принимается как 12, дробь — ошибка («целое + масштаб»).
- Необязательные расширения связи: `rework_limit` (лимит ремонтов по КД), `closes_access_to` (закрываемые зоны явно). Ключи с «_» в начале — комментарии.
- Повторный импорт того же файла (тот же отпечаток Стрибог-256) — дубль с прежней квитанцией; изменённый файл — новая версия состава.
- Неизвестная мажорная `format_version` — отказ «неизвестная версия формата» (переобработка после повышателя, AD-20).

## 4. Связи → объекты нормативного слоя

Связи сборки не остаются «картинкой»: модуль `cad` переводит их в зоны и ограничения, которые исполняет движок (AD-18):

| Связь | Что это | Что появляется в нормативном слое | Какое правило срабатывает |
|---|---|---|---|
| W-1 | сварной шов фланца с патрубком | зона изделия «шов W-1» — объект учёта **лимита ремонтов** | петля доработки с лимитом (FR-18): четвёртая доработка шва при лимите 3 без отдельного разрешения блокируется |
| J-1 | болтовое соединение крышки | зона «болтовое соединение J-1» со свойством **«закрывает доступ к зоне»** | скрытые работы (FR-20): начать установку крышки без завершённой проверки закрываемой зоны нельзя; разборка — запись вмешательства (FR-21) |
| S-1 | уплотнение | зона «уплотнение S-1» и **порядок установки** «до крышки»; срок хранения партии уплотнений | предусловие операции (FR-17): просроченная партия или нарушенный порядок — блокировка |

Как это считается в коде (`domain/cad.Translate`): лимит ремонтов шва берётся из файла (`rework_limit`), а если его там нет — из утверждённого ТП: шаг BPMN с `reworkLimitScope="zone"`, чьи зоны — участки связи (для фланца — `welding.weld`, `reworkLimit="3"`, зоны `W-1.U1…U8`); нет ни там, ни там — ограничение создаётся без числа с пометкой «задаёт технолог». Закрываемые J-1 зоны — `closes_access_to` или уплотнения между теми же деталями (`S-1`); шаг скрытых работ — шаг с `closesZoneAccess`, содержащим зону (`assembly.cover_install`). Порядок S-1 — уплотнение до детали, которую закрывает болтовое соединение (крышки); шаг — первая операция с `zoneRef` S-1 (`assembly.seal_install`). Резьбовое соединение J-2 даёт зону и ограничение `torque` (12 Н·м ± 10 %, контровка). Зона лежит на наименьшем общем родителе соединяемых позиций (J-2 — на крышке). Всё это — в факте `cad.assembly.imported` (зоны, ограничения, дерево) и в операции `cad.assembly.list`.

Важные характеристики `critical_characteristics` сопоставляются с методами контроля и покрытием видов дефектов (FR-14) в плане контроля версии процесса. Импорт даёт **черновик** изменений нормативного слоя; действующим он становится только после утверждения кворумом (FR-23).

## 5. Источник достоверных сведений и сопоставление идентификаторов

- Источник истины по конструкторскому составу, обозначению, исполнению и версии КД — КОМПАС-3D / PLM. Источник истины по учётной карточке номенклатуры — ERP.
- Внешний ID позиции — обозначение (+ исполнение) + имя файла + хеш файла; `UniqueNum` КОМПАС уникален только внутри документа и ключом не служит.
- **Правило сопоставления с 1С** (проектное предположение): позиция состава связывается с номенклатурой 1С по обозначению по ЕСКД (в 1С — реквизит номенклатуры, где хранится обозначение, например «Артикул»; сверяется по `$metadata`). Найдено одно совпадение — две записи `reference.external_id.mapped` (КОМПАС и 1С) указывают на один наш тип изделия. Не найдено или найдено несколько — отчёт о расхождениях, без автосоздания номенклатуры. Промышленный путь — сквозной MDM-идентификатор (ПОЛИНОМ:MDM / ЛОЦМАН:PLM), тогда сопоставление идёт по нему.
- **В коде:** наш тип изделия — `domain/cad.ItemTypeID`: обозначение по ЕСКД (первое слово с точкой) латиницей без кода документа («ФЛ-100.00.000 СБ» → `FL-100.00.000`) — то же, что делает адаптер 1С с реквизитом «Артикул» и адаптер Галактики с обозначением из каталога МЦ; стандартные и покупные изделия без обозначения ЕСКД — всё обозначение латиницей без пометок «[П]» («Болт М6×20 [П]» → `BOLT-M6-20`). Импорт пишет `reference.external_id.mapped` (система `kompas`, вид `item_type`) для сборки и каждой позиции. Сверка с номенклатурой учётной системы — через порт `application/cad.Nomenclature`: позиции без соответствия — расхождения `not_in_erp` в факте импорта; номенклатура ещё не получена — одна запись `not_checked`.
- Если в файл будет добавлена ссылка на номенклатуру 1С (в формате 1.0 её нет), она проверяется, а не принимается на веру: расхождение с обозначением — сигнал.

## 6. Ошибки импорта

| Ошибка | Поведение |
|---|---|
| файл не проходит схему (нет `geometry`, нет `version`, пустое обозначение) | отказ операции `400 api.validation_failed` с полем (JSON Pointer) — загрузивший видит причину сразу; в журнал ничего не пишется |
| неизвестная `format_version` | отказ `400 api.validation_failed` с полем `/format_version` и пометкой «переобработка после появления повышателя» (AD-20) |
| тот же файл повторно | дубль, ничего не меняется (FR-31) |
| ссылка связи на несуществующую позицию | отказ `400 api.validation_failed` с полем связи (`/links/1/from`) |
| позиция не сопоставлена с номенклатурой ERP | версия состава принимается, позиция помечена «нет соответствия», отчёт о расхождениях и задача администратору |
| конфликт соответствия ID | сигнал, без перезаписи (AD-18) |

## 7. Путь к прямому подключению

Программный интерфейс КОМПАС-3D — **COM (API5 и API7)**, только под Windows при установленном и лицензированном КОМПАС (проверено по документации SDK). Штатного экспорта состава изделия в XML нет — только геометрия (STEP AP203/214/242, JT и др.), поэтому файл условной сборки — наш формат.

1. **Экстрактор через COM API7** (ближний шаг): небольшая программа на рабочем месте конструктора или на Windows-шлюзе открывает сборку только на чтение (`Kompas.Application.7` → документ → `TopPart`), обходит уникальные компоненты (`IPart7.PartsEx`), берёт обозначение (`Marking`), признаки «деталь / стандартное изделие» (`Detail`, `Standard`), материал, массу, количество вхождений (`GetInstanceCount`) и формирует тот же файл с `source.system = "КОМПАС-3D (COM API7)"`. Связи и важные характеристики берутся из атрибутов модели или дописываются технологом. Windows-шлюз — отдельный узел со своим ключом устройства, файл идёт в `ant` через edge-агент как подписанный факт.
2. **ЛОЦМАН:PLM** (промышленный путь): в промышленности КОМПАС → ERP идёт через PDM, а не из САПР. Адаптер подписывается на изменённые объекты через интеграционную шину ЛОЦМАН (XML: описательная часть + объекты с атрибутами и связями) или SDK сервера приложений; ID — идентификатор объекта ЛОЦМАН + номер версии, связь с 1С — через MDM-идентификатор. Серверная часть ЛОЦМАН работает под Linux.

В обоих случаях меняется только адаптер `infrastructure/integration/cad/‹источник›`; формат для ядра и правила нормативного слоя — те же.

## 8. Смежный узел: САПР ТП ВЕРТИКАЛЬ (описание, критерий О5)

САПР ТП ВЕРТИКАЛЬ (АСКОН) штатно экспортирует техпроцесс в XML «с учётом структуры и связей» и содержит **контрольные операции**, **контролируемые параметры** (передаются в контрольную операцию из предшествующих операций) и **режимы контроля**, созданные по маркерам чертежа КОМПАС (проверено по руководству пользователя). Это готовый источник контрольных точек и характеристик для **черновика** версии процесса:

| ВЕРТИКАЛЬ | Черновик BPMN `ant` |
|---|---|
| межцеховой маршрут | дорожки цехов, шаги перемещения |
| операция (цех, оборудование, норма времени) | задача BPMN со свойствами `urn:ant:bpmn-ext:1` (норма, цех) |
| контрольная операция | задача контроля человеком — точка предъявления |
| контролируемый параметр, режим контроля | характеристика с допуском и методом в плане контроля |

Результат — только черновик: действующей версию делает утверждение кворумом (FR-23). Схема XML ВЕРТИКАЛИ не проверена (нужен образец файла) — это **описание, не MVP**.

## 9. Граница эмуляции (NFR-TEST-2)

Эмулятора КОМПАС нет и он не нужен: кейс допускает файл условной структуры (§3.3). В MVP — импорт файла ФЛ-100.00.000 СБ через обычный приём; экстрактор COM API7 и адаптер ЛОЦМАН — описание.

**Где в коде:** `backend/internal/infrastructure/integration/cad/kompas/` (чтение файла, порт `application/cad.Reader`), `backend/internal/domain/cad/` (дерево, зоны, ограничения, соответствия, расхождения), `backend/internal/application/cad/` (операция `cad.assembly.import`, факты через обычный приём, проекция `cad.assembly`), схема — `contracts/integrations/cad/assembly.schema.json`.

## В коде (эпик 31)

- **Операция импорта:** `POST /api/v1/cad/assemblies` (`cad.assembly.import`, тело — `file_name` и `content` в base64; модуль `cad`), чтение — `GET /api/v1/cad/assemblies` (`cad.assembly.list`: дерево, зоны, ограничения, характеристики, расхождения). Факты идут через обычный приём: источник `cad.kompas`, вид «импорт»; `event_id` факта — UUIDv5 от отпечатка файла.
- **Тип события:** `cad.assembly.imported` (расширен совместимо: дерево — `item_type_id`, `parent_item_type_id`, `total_quantity`, `tracking`; `zones`, `constraints`, `characteristics`, `discrepancies`); соответствия — `reference.external_id.mapped` (система `kompas`). Отдельного типа «расхождения» нет — они в факте импорта.
- **Связи в нормативном слое:** ограничения `rework_limit` (W-1), `closes_access` (J-1), `install_order` (S-1), `fastening`, `torque` с шагом процесса из BPMN (`reworkLimit`/`reworkLimitScope`, `closesZoneAccess`, `zoneRef` — `contracts/bpmn-ext/`). Дерево и зоны — черновик справочника типов изделий: `reference.item_type.defined` утверждает человек (AD-31, модуль `reference`).
- **Контрактный тест:** `go test ./internal/infrastructure/integration/cad/... ./internal/domain/cad/...` — эталон по схеме, импорт ФЛ-100.00.000 СБ даёт дерево, лимит ремонтов шва 3 (по ТП) и «закрывает доступ к зоне» S-1 у J-1, дубль, ошибки формата с полем.
- **Коды ошибок импорта:** `api.validation_failed` с полем; отдельного семейства `cad.*` в `contracts/errors.yaml` нет.
- **Реквизит 1С для сопоставления** — «Артикул» (как в адаптере 1С); сверка по `$metadata` — у адаптера 1С.
