# Эталонные сообщения интеграций

Схемы и примеры для контрактных тестов адаптеров 1С, Галактики, MES и КОМПАС. Описание — в [docs/integrations/](../README.md). Все ID и номера условные.

> **Статус.** Эталон процессной сессии: сообщения по сюжету сценариев [scenarios/process-session/](../../../scenarios/process-session/README.md). Это не часть `contracts/` — там источники контрактов системы, из которых идёт кодогенерация; сведение полей — по плану.

```
python3 -m pip install jsonschema lxml   # jsonschema >= 3.2 (draft-07), lxml — для XSD
python3 docs/integrations/examples/check.py   # код выхода 0 — всё сошлось
```

`check.py` проверяет каждый пример против его схемы, XML Галактики — против XSD, и 15 заведомо неправильных сообщений, которые схемы обязаны отвергнуть: «оценка невозможна» как итог ЗТ, гипотеза в сообщении в 1С, текст причины в блоке MES, снятие блока без человека, геометрия в файле КОМПАС и другие.

| Папка | Схемы | Примеры | Документ |
|---|---|---|---|
| `1c/` | `control-result.request.schema.json`, `response.schema.json` | 3 запроса «результат контроля» (Ф-001 ЗТ-6; НС-И1 ЗТ-Р; П-117 ЗТ-1), 5 ответов (201, 200 дубль, 409, 422, 503) | [1c.md](../1c.md) |
| `galaktika/` | `qc-galaktika-1.0.xsd` | 9 XML-пакетов: заказ ПЗ-0917, партия П-117, акт на брак НС-И1, статус МЦ Ф-001 и П-117, сдача Ф-001, квитанции `accepted` и `rejected` | [galaktika.md](../galaktika.md) |
| `mes/` | `job-order`, `job-response`, `material-sublot-hold`, `test-result`, `acknowledge` | 9 сообщений: наряд СВ-017-2 и его ход, блок Ф-017, снятие Ф-008, отказ MES по Ф-221, операция принята (Ф-001 ЗТ-2), не принята (НС-И1), квитанции | [mes.md](../mes.md) |
| `kompas/` | `assembly.schema.json`, `discrepancy-report.schema.json` | файл сборки ФЛ-100.00.000 СБ «Б» (файл сборки процессной сессии), отчёт о расхождениях с 1С | [kompas.md](../kompas.md) |

Имена файлов: `in.` — к нам, `out.` — от нас; для 1С — `request` / `response`. Схемы исходящих строгие (`additionalProperties: false`), входящих — терпимые к новым полям.
