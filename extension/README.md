# Главный — подпись: расширение браузера и агент токена (эпик 38)

Подпись решений системы «Главный» ключом человека на его рабочем месте (FR-69,
AD-14, решение Д-72). Порт подписи один, адаптеров два:

| Адаптер | Где ключ | Окно подтверждения | Класс хранения (в акте ключа, подписи, `make verify`) |
|---|---|---|---|
| **Ключ в браузере** (демо держится на нём) | файл ключа загружен в расширение, хранится зашифрованным под PIN (argon2id + AES-256-GCM) | окно расширения | `software_browser` / `extension` |
| **Физический ключ** (эталон) | «токен» у агента `token-agent`; PIN — только в окне агента | окно локальной программы (macOS — системный диалог) | `hardware_token` |

Система рассчитана на физические ключи; ключ в браузере — умышленно сниженный
порог безопасности ради работы с любого устройства (Д-72).

Подпись считает **тот же Go-пакет**, что у сервера (`backend/cmd/token-agent/internal/agent`
поверх `domain/signing`), собранный в WebAssembly (`signer.wasm`): ГОСТ Р 34.10-2012 и
ML-DSA в WebCrypto нет. Пакет сам собирает подписываемое событие-команду, сам
считает отпечаток и сводку (что видит человек в окне — то и подписывается),
отклоняет уровень 1 вне вкомпилированного перечня («годен» уровнем 1 не
подписывается), ограничивает частоту уровня 1 (20 в минуту) и ведёт локальный
журнал подписанного (сменный рапорт — корень Меркла по нему).

## Сборка пакета

```
make token-agent                                   # на машине сборки (Docker)
make token-agent DEMO_KEYS=~/cosmo-controller/.demo-keys/token-agent   # положить в пакет демо-ключи стенда
```

Итог — `dist/glavny-token-agent-macos-arm64.tar.gz`:

```
glavny-token-agent/
  extension/        распакованное расширение (manifest, signer.wasm, wasm_exec.js, страницы)
  bin/              token-agent: darwin-arm64 (Mac на Apple Silicon), darwin-amd64, linux-amd64
  install.sh        установка агента токена и манифеста Native Messaging
  demo-keys/        демо-ключи персон (если были в DEMO_KEYS) — секреты демо-стенда
  README.md
```

Перед сборкой идут тесты ядра (`go test ./cmd/token-agent/...`) и сверка
«отпечаток WASM = отпечаток Go» в Node (`extension/test/wasm-vectors.mjs`).

## Как поставить и проверить на Mac (ключ в браузере)

1. Скопируйте пакет на Mac и распакуйте: `tar -xzf glavny-token-agent-macos-arm64.tar.gz`.
   Если скачивали браузером — снимите карантин: `xattr -dr com.apple.quarantine glavny-token-agent`.
2. Chrome (Chromium, Яндекс Браузер): `chrome://extensions` → включить **Режим
   разработчика** → **Загрузить распакованное** → выбрать каталог
   `glavny-token-agent/extension`. Появится «Главный — подпись»
   (ID `aagmahobgjnlhbbkpppkfefjhocfpjce` — фиксирован полем `key`).
3. Значок расширения → **Управление ключом** → «Файлы ключа» → выберите
   демо-ключ контролёра `demo-keys/ins-01-ta@1.key.json` (для профиля hybrid —
   ещё `ins-01-ta-pq@1.key.json`) → дважды PIN (не короче 4 символов) →
   **Загрузить и зашифровать**. Ключ станет «готов — PIN введён».
4. Откройте систему «Главный» (адрес `http://127.0.0.1:…` или `http://localhost:…`
   разрешён сразу; другой адрес — «Где ключ» → «Дополнительный адрес системы» →
   **Разрешить**) и войдите контролёром (INS-01). Индикатор **«Токен»** в шапке —
   подсказка «Ключ готов к подписи · INS-01 · ключ в браузере».
5. Стол контролёра → несоответствие → «Подтвердить несоответствие» (или другое
   решение) → «Подписать токеном». Откроется **окно расширения** «Главный —
   подпись» со сводкой (действие, изделие, содержание, основание, подписант,
   уровень 2, отпечаток), посчитанной пакетом подписи; **Подписать** → команда
   уходит с конвертом DSSE, в журнале расширения («Управление ключом» →
   «Локальный журнал подписанного») появляется запись.
6. Отказ уровня 1: «Управление ключом» → **Попробовать подписать «годен»
   уровнем 1** → «Отклонено пакетом подписи — Уровень подписи не допускается: …».
7. Блокировка: значок → **Заблокировать** (или блокировка экрана macOS) — PIN
   спросит следующее окно подписи; индикатор «Токен» — «Ключ загружен — PIN
   спросит окно подписи».

Где расширений нет (планшет, телефон) — тот же пакет подписи в хранилище
страницы (`storage_variant: page`) — в этой сборке не включён (см. отчёт эпика).

## Физический ключ (агент токена) — каркас

1. `./install.sh` — кладёт `token-agent` в `~/Library/Application Support/Glavny/token-agent/bin/`
   и пишет манифест Native Messaging `ru.glavny.token_agent.json` для Chrome,
   Chromium и Яндекс Браузера (в `allowed_origins` — только ID расширения).
2. Положить ключ на «токен»: `…/token-agent import -key demo-keys/ins-01-ta@1.key.json`
   (PIN спросит программа; `-token /Volumes/‹флешка›` — «токен» на съёмном
   носителе: извлекли носитель — PIN забыт). Класс в хранилище — `hardware_token`.
3. Расширение → «Управление ключом» → «Где ключ» → **Физический ключ** →
   **Сохранить**; **Проверить агент токена** покажет владельца и класс.
4. Подпись решения — окно подтверждения и PIN в **системном диалоге macOS**
   (локальная программа, не страница).

`token-agent status` — что на токене и где манифест.

## Ограничения MVP

- Окно подтверждения ключа в браузере — страница расширения: подменённое
  расширение может показать одно, а подписать другое (AD-34); цель — окно
  локальной программы (так сделано у агента токена).
- Демо-ключи персон `‹псевдоним›-ta@1` зарегистрированы генезисом как
  `software_browser` / `extension`; их же можно положить на «токен» агента для
  проверки протокола, но класс по акту останется `software_browser` — реестр
  ключей, а не заявление клиента, решает, каким классом подписано.
- PKCS#11-токен, постоянная служба агента с сокетом пользователя и сброс PIN
  при блокировке экрана в агенте — следующий шаг за тем же протоколом.
