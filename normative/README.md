# normative — затравка нормативного слоя (seed)

«Как должно быть» для демо-изделия «фланец люка гермокорпуса в сборе» ФЛ-100.00.000 СБ (PRD §11.15, §11.19). При первом `docker compose up` `ant init` загружает это в блок генезиса (AD-33): `normative.version.loaded` (BPMN как загружен + отпечатки файлов), записи `reference.*`, `policy.*`, `access.*`; подписи кворума — ключами генезиса. Дальше части слоя меняются только новыми версиями через кворум и переходят модулям-владельцам (эпики 17, 19, 20, 26, 28).

## Стартовый процесс: что изменено относительно черновика процессной сессии

Смысл маршрута не менялся. Изменения (решения дирижёра Д-4…Д-8, `~/ant/_bmad-output/implementation-artifacts/decisions.md`):

1. Проставлены `stepKey` и свойства FR-12 у всех 87 узлов и свойства цехов у 5 дорожек.
2. 19 неявных слияний заменены явными исключающими шлюзами `J_‹узел›` (Д-6); DI дополнена.
3. Язык условий — `urn:ant:expr:1` (Д-7); `||` записано как `or`.
4. terminate, старт по сообщению из 1С (`triggerEventType = erp.order.received`) и граничный таймер окна кромок (`timerScope = until_started`) — как у процессной сессии (Д-4, Д-5, Д-8).

Новые версии от процессной сессии принимаются тем же преобразованием: `step_key` существующих узлов не меняются.
